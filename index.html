Codex CLI 的核心代码是开源的，但一万多个提交不会自己解释自己。这个站把五条主干线路 做成了能上手的仪器：单步走完一轮 Agent 循环，逐层搭出一次模型请求， 切换沙箱模式看权限判定，放一遍客户端协议报文，翻 136 个 crate 的分层图谱。

左边那排编号就是目录：00 总览，01–05 五条线路，06 术语速查，07 深水区支线。 正文里带 虚线下划线 的词， 悬停或点一下就能看到人话解释。

01

先给模型一个身份

base_instructions 随 CLI 打包：「你是 Codex CLI、一个基于终端的编码助手」——外加可用操作清单。config.toml 里指定 model_instructions_file 时整体替换这一层。

02

再给它一份工具清单

内置 shell、API 侧工具、MCP 接入的外部工具，合并成一份 tools 字段。模型照着它决定调什么——注意只有内置那部分被沙箱管着。

03

一条沙箱声明

role=developer 的消息，告诉模型它当前被允许碰什么：工作目录、临时目录、网络。它是描述，不是墙本身——墙在 03。

04

你的长期偏好（可选）

config.toml 里的 developer_instructions，存在才注入。适合放「永远用中文回复」这类个人约定。

05

沿目录层叠的项目约定

从 ~/.codex 沿 git root 一路读到当前目录的 AGENTS.md，越近的越具体。层叠总量受 32 KiB 上限约束，触顶截断发生在读入侧。

06

告诉它身处的机器

role=user 的环境消息：当前工作目录、shell。换一台电脑这层就不一样——模型知道自己在哪，才知道命令该怎么写。

07

全量历史，然后出站

之前的对话逐条重发（含 reasoning 与工具输出），保持请求无状态。POST /responses 出站，SSE 开始回流——01 循环回路接手。

03权限沙箱

6 动作 × 3 模式 × 审批轴

同一个动作，三种模式三个下场：read-only 连临时目录都不给写，workspace-write 放行工作区但拦下越界路径，danger-full-access 直接裸跑。判定器底下压着三套真实的内核机制（Seatbelt、Landlock+bwrap、WFP），选平台、选模式、点动作，结论和理由当场给。

选系统、选模式、选一个具体动作，直接给判定和理由。
