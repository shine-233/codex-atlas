会话与事件

术语人话解释在哪看
Agent 循环模型不是一问一答就完事：它发一个动作（比如执行命令），拿到结果写回历史，再决定下一步——这个「动作→结果→再决策」的圈就是 agent loop。01
turn（轮）用户一次任务的完整生命周期。一轮里模型可能被调用好几次，数「轮」不等于数请求次数。01
run_turn / 采样核心里负责「向模型要一次回复」的函数。每次被调前都重新组装一遍 Prompt，把完整历史带上。01 第9站
队列对Codex 核心的骨架：两条异步通道，一边收指令（Submission 进），一边吐事件（Event 出）。整个系统绕着它转。01 第6站
Op / EventMsg核心内部指令和事件的类型前缀。Op::UserInput 是「用户说了一句话」，EventMsg::* 是往外广播的各种消息。01 第6站
needs_follow_up「本轮还没完」的标记。只要这轮出现了工具调用就置 true，历史写回后再采样一圈；纯文本回复时才收束。01 第11–13站
TurnComplete一轮任务正式结束的事件，由 task wrapper 统一发出。看到它，这轮的账就结了。01 第13站
steer_input你在一轮跑着的时候又发了句话？这个函数把你这句并入正在运行的轮次，而不是排队等它跑完。排队变成了并线。01 第7站

请求构成

术语人话解释在哪看
Responses APIOpenAI 的模型 HTTP 接口。Codex 每次采样都向它 POST 一次请求，然后逐条读回流式响应。01 第10站
SSEServer-Sent Events：服务器往客户端单向推流的 HTTP 机制。模型的字是一个一个流回来的，底层就是它。01 第10–11站
base_instructions随 CLI 打包的模型身份指令（「你是 Codex CLI……」），对应仓库里的 gpt_5_codex_prompt.md。七层负载的第 1 层。02 第1层
developer_instructions你在 ~/.codex/config.toml 里写的可选指令层。放长期偏好；项目约定请走下一层的 AGENTS.md。02 第4层
AGENTS.md 层叠从 ~/.codex 沿目录一路读到当前目录的项目约定文件，越近的越具体、覆盖越通用的。总量受 32 KiB 默认上限约束。02 第5层
previous_response_id官方 API 用来续接会话的参数。Codex 有意不用它：每次全量重发历史，保持请求无状态，零数据保留部署才能兼容。01 第10站
提示缓存命中服务端把重复的历史前缀缓存起来，命中部分按约一折计费，全量重发的总账单因此从平方增长退回近似线性。01 成本对照
auto_compact_limittoken 总量超过阈值就自动压缩历史的开关，压缩走 /responses/compact，压完带着加密内容继续对话。02 答疑表
tool spec（工具清单）发给模型的可用工具说明书：名字、参数形状。模型照着它决定调什么。内置、API 侧、MCP 三类合并成一份。02 第2层

权限与沙箱

术语人话解释在哪看
三档沙箱模式进程能碰什么的硬边界：read-only 只出主意不动手；workspace-write 工作目录加临时目录可写、默认断网；danger-full-access 全放开。03
四档审批策略「什么时候先问你」的软规则：untrusted 全都先问；on-failure 失败才升级；on-request 模型自己申请；never 从不打扰。和沙箱模式是两条独立的轴。03
SeatbeltmacOS 的沙箱强制机制。Codex 为每条命令生成一份 profile 规则，再用 sandbox-exec 套着启动。03
Landlock + seccompLinux 内核侧的两道闸：Landlock 过滤文件树访问，seccomp 收窄可用系统调用。另有 bwrap 容器路线作备选。03
WFPWindows Filtering Platform：Windows 上管网络流量的内核框架，Codex 用它做网络层管控。03
条件放行判定器里的琥珀色格子：沙箱本身不放行，但你的审批策略允许弹窗，点头才升级执行一次。03
shell-escalation审批升级流的实现 crate：沙箱内拿不到的权限，经你批准后换一种方式重跑。05 B3
execpolicy执行策略引擎：判定哪些命令属于安全白名单，可以免审批直接跑。05 B4
项目信任第一次在某个目录里启动会弹「信任这个目录吗」；点过的目录写进 config 的 projects 表，之后免确认。信任的是「这里的 AGENTS.md 和命令我认」。07 B 房
MCPModel Context Protocol：给模型接外部工具的标准协议。重点：经 MCP 接的工具不在 Codex 沙箱管辖范围内，防护由提供方自己负责。03 底部

协议通道

术语人话解释在哪看
App Server把 Codex 核心包装成一个 JSON-RPC 服务的进程。IDE 插件、桌面 App、TUI 都是它的客户端。04
embedded 模式本地默认形态：App Server 和 TUI 跑在同一个进程里。即便同进程，客户端与服务端的协议边界照样存在。01 第3站
stdio JSONL主传输方式：在标准输入输出上每行一条 JSON。简单、可调试，IDE 场景够用。04
Thread / Turn / Item协议三原语：Thread 是会话容器（可恢复、分叉、归档）；Turn 是由输入发起的一轮工作；Item 是里面最小的条目单位。04
started → delta → completedItem 的生命周期三步：started 到达即可渲染占位，delta 流式补全（打字机效果靠它），completed 落定。04 第7–9条
commandExecution/approval服务端反向发给客户端的审批请求。它到达时整轮暂停，等客户端给一个应答——「双向」两个字就体现在这。04 第11条
rollout / resume / fork轨迹落盘、断线恢复、时间线分叉。事件历史持久化保存之后，客户端随时能接着上次的现场继续。04; B2
